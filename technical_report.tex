\section{Executive Summary}
This technical report details the \textbf{P2P Web Share} project, a lightweight, decentralized peer-to-peer (P2P) file-sharing web application. It enables direct browser-to-browser file transfers without storing file data on a centralized server, ensuring high privacy and zero server-side bandwidth costs for file transmission.

\section{System Architecture \& Technology Stack}
The application utilizes a hybrid decentralized architecture comprising two primary layers:
\begin{enumerate}
    \item \textbf{Frontend Client:} A React.js interface that handles user interactions, local file reads via the FileReader API, and WebRTC data channel establishment. Cryptographic operations are performed locally using the Web Crypto API.
    \item \textbf{Signaling Server:} A minimalistic Node.js and Socket.io backend. It strictly coordinates the initial WebRTC connection handshake (SDP offers/answers and ICE candidates) without accessing the data stream.
\end{enumerate}
The tech stack is rounded out with custom CSS for a modern, glassmorphism-based UI, and Vite as the build tool for optimized frontend bundling.

\section{Feature Implementation Details}

\subsection{Share Room Creation \& Handshake}
\begin{itemize}
    \item \textbf{Room Creation:} Users drop a file (limited to 50 MB for memory safety) into the UI. The client generates a unique Room ID via \texttt{crypto.randomUUID()} and provides an invite link.
    \item \textbf{Signaling:} The sender and receiver connect to the Node.js server. The sender creates an \texttt{RTCPeerConnection} and SDP Offer. The server relays this metadata (along with ICE candidates) to the receiver, establishing the peer-to-peer network path. The server enforces a strict two-peer limit per room.
\end{itemize}

\subsection{Direct P2P Data Transfer}
\begin{itemize}
    \item \textbf{Data Channel:} The sender opens an \texttt{RTCDataChannel} configured with \texttt{ordered: true} to guarantee packet sequence.
    \item \textbf{Streaming:} To prevent UI thread blocking, the file is sliced into 32 KB chunks using the \texttt{Blob.slice()} API and converted into an \texttt{ArrayBuffer} immediately before transmission.
    \item \textbf{Buffer Management:} Transmission pauses if the channel's \texttt{bufferedAmount} exceeds 256 KB, preventing packet loss and memory overflow.
\end{itemize}

\subsection{Cryptographic Integrity}
To guarantee zero data corruption, rigorous cryptographic checks are enforced.
\begin{itemize}
    \item \textbf{Hashing:} The sender computes a SHA-256 hash for both the entire file and each 32 KB chunk.
    \item \textbf{Verification:} A \texttt{chunk-header} containing the expected hash is sent before the binary payload. The receiver validates the incoming payload against the header. Upon transfer completion, the receiver validates the reassembled Blob against the master file hash.
\end{itemize}

\subsection{Progress Tracking \& Error Handling}
\begin{itemize}
    \item \textbf{Metrics:} The React state tracks transferred bytes and dynamically calculates the throughput speed (MB/s) and completion percentage in real-time.
    \item \textbf{Disconnect Resilience:} The \texttt{RTCPeerConnection} and the signaling server monitor for connection drops. If a peer disconnects abruptly, a \texttt{peer-disconnected} event halts the transfer and alerts the remaining user gracefully.
\end{itemize}

\subsection{Automated Download}
Once all chunks are verified, the \texttt{ArrayBuffer} sequence is merged into a \texttt{Blob}. The client invokes \texttt{URL.createObjectURL(blob)} to generate a temporary download link, automatically triggers a click via an injected anchor (\texttt{<a>}) element, and immediately revokes the URL to release memory.

\section{Conclusion}
The P2P Web Share MVP successfully delivers a secure, serverless file-transfer platform. By maximizing the native WebRTC and Web Crypto APIs, the system balances robust technical constraints with a highly responsive user interface, achieving all operational requirements effectively.
